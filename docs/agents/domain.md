# Domain docs

This repo uses a single-context layout:
- `CONTEXT.md` at the repo root.
- Architecture decision records in `docs/adr/`.

Before exploring, read `CONTEXT.md` and relevant ADRs.

If these documents are absent, proceed silently.
The domain-modeling skill creates them as terminology and
decisions are resolved.

Use the glossary's terms when naming domain concepts.
Note real vocabulary gaps for domain-modeling.

Explicitly flag proposals that contradict an existing ADR,
identifying the decision and why it should be reconsidered.
